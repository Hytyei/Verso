# Verso v1.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Flutter Windows app that tracks app features by version. It has a board view, a zoomable timeline, Liquid Glass chrome, light and black-warm dark themes, and local SQLite storage ready for sync.

**Architecture:**
- Drift (SQLite) tables, with soft deletes and fractional sort keys, sit behind small repository classes that return Drift `Stream`s.
- Riverpod providers expose those streams to widgets.
- The UI is split into shell / board / timeline / editors.
- All glass goes through one `GlassSurface` widget, so real refraction and the fallback can be swapped in a single place.
- The timeline is a single `CustomPainter` driven by a pure `TimelineScale`.

**Tech Stack:** Flutter 3.44 (Windows desktop), Dart 3.12, drift + drift_flutter + sqlite3_flutter_libs, flutter_riverpod, window_manager, uuid, path_provider, image (thumbnails), desktop_drop, pasteboard, liquid_glass_renderer (if Task 1 passes), Inter font (bundled).

**Spec:** `docs/superpowers/specs/2026-11-08-verso-design.md`

## Global Constraints

- Project root: `D:\RandD\Windows Apps\Verso\v1.0.0\`. Package name `verso`. Windows only for now, but no Windows-only APIs outside `lib/platform/`.
- Every table has `id` (UUID v4 text PK), `createdAt`, `updatedAt` (UTC epoch ms), `deleted` (bool). Queries never return `deleted = true` rows.
- Any write sets `updatedAt = now`. A delete only sets `deleted = true`.
- Ordering is by `sortKey` text (fractional index). A move rewrites only the moved row.
- Attachments go to `%APPDATA%\Verso\attachments\<uuid>.<ext>` with `<uuid>.thumb.png` (512 px max side). The DB lives at `%APPDATA%\Verso\verso.db`.
- Default tags for a new project: Feature, Fix, UI, Backend, Polish.
- Light palette and dark palette exactly as spec §6.1 / §6.2. Palette slots 0–3 map light Blue/Amber/Coral/Slate ↔ dark Amber/Coral/Rose/Sand. Custom colors are stored as ARGB with a flag and used as-is.
- Glass only on chrome and controls (title bar, sidebar, toolbar, segmented control, floating buttons, popovers, sheets, drag ghost). Never on feature cards.
- Motion: spring response ~0.35 s, damping ~0.85. Animate only transform and opacity, except the height collapse on delete. Reduce motion (setting or Windows) swaps springs for 150 ms crossfades.
- Font: Inter, bundled under `assets/fonts/`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A very long feature title** (2,000+ chars, no spaces, or many newlines) must wrap in the card and in the editor without overflow errors or a frozen frame. Test in Task 7.
2. **Moving a feature into an empty version, or to the very top/bottom of a column, repeatedly** must keep a valid, strictly ordered sortKey (no collisions, no unbounded growth from moving one item back and forth). Test in Task 2.
3. **Versions or features with no dates, or an end date before the start date,** must not crash the timeline. Undated versions go to the Undated tray, and inverted ranges are normalised by swapping. Test in Task 9.
4. **Dropping a non-image or corrupt file onto a card** must be rejected with a toast and nothing stored. A huge image (8000 px) must be thumbnailed off the UI thread. Test in Task 4.
5. **Undo after deleting a version that contains features** must restore the version and all its features, sub-items, tags links and attachments. Test in Task 4.
